# Malody 4K 制谱

对于歌单或多首请求，优先由 Codex 使用本 Skill 安排自动任务，减少逐首在前端提交的操作；网页用于试听试玩、区域编辑和候选 A/B。单曲也可通过网页或 `tools/generate.py`。这是一套操作本地服务的工作流，不是独立制谱引擎或网页歌单功能。用户指定的难度、引擎、谱型与尝试次数优先于示例。

先定位项目根目录（含 `malody_studio/`、`tools/` 和 `README.md`），使用已经部署的服务和环境，检查健康状态、引擎与队列，不另起占用显存的模型服务。运行数据放在项目内 `work/<batch>/`、`data/`、`outputs/`，遵守用户指定的位置，不假定固定盘符。接口和准备步骤见 [service-api.md](references/service-api.md)；歌单任务说明见项目根目录的 [docs/codex-workflow.md](../../docs/codex-workflow.md)。

将歌曲身份和核验结果写入来源台账，准备高级项目后冻结请求清单，通过 `tools/batch_generate.py` 串行提交正式队列并保存状态。原曲身份、实际参数、模型与校准版本、请求 ID 和批次回执须可追踪。未知提交结果先核对持久化回执与任务，不盲目重复 POST；失败或 partial 请求不能用同一 ID 重复提交。新候选单独保存，并在控制器之外核算每首／每档总尝试预算，失败也按用户约定计数。控制器完成只是生成完成，仍需选版、导出和质量检查。后续定期检查仅在用户要求且环境支持调度时安排，不能因读取 Skill 自行创建定时任务。

生成前确认音频的曲名、音乐人、版本、时长和完整解码。联网选曲须核对确切歌曲或视频身份，不用相似曲名替代。模型生成的 BPM 不是已经验证的音乐 BPM；节拍检测和 BPM 桶可以帮助选择生成条件，但不能据此强制吸附模型音符或改动原曲绝对时间。V32 的难度条件与目标 NPS 是生成请求，不是实际谱面等级或保证输出物量。新 V32 请求在普通台和高级台均逐档独立生成；历史母谱分层路线只用于相应冻结任务的重试，不能重新套用到新路线。只有模型产生的音符头能进入谱面，不以声学起音或扩和弦补足密度。

封面和作者是交付验收的一部分。使用与该录音版本对应、可核实的音乐人和封面；不要猜图或填 `Unknown`。下载原图时验证格式、解码和哈希，不设置任意的文件大小或像素大小上限。MCZ 应包含图片，各档 MC 的 `meta.background` 都须指向包内图片，`meta.song.artist` 应与核实的署名一致。没有可靠资料时记录问题，让候选保持未交付状态；不要默默使用默认封面。独立回读 MCZ，并在实际导入游戏后检查图片、作者、音频与谱面文件。

谱面质量要在**生成后按最终 MCZ 实测**。分别检查各难度的平均 NPS、活动段与短时峰值、和弦分布、长按、同轨连续按压和两档差距；全曲平均密度与模型条件分数都不能代替局部手感。源 BPM 会影响模型看到的音乐节奏，但不能单凭 BPM 推断游戏难度。若实际输出偏离目标，先核对输入版本、冻结 BPM 桶、难度条件、模型原始头数、融合与导出损失；在获准的尝试次数内调整下一候选。次数耗尽后只能从已有模型音符中选择或作有界修正，并如实报告未达标，不把容易或过难的谱面仅凭标签称作目标难度。真实试玩准确率应单独记录，不能由自动指标推断。

若获准从同一录音的既有模型版本补回音符，须同时限制全曲新增比例、原本稀疏的小节以及短时窗口的相对增幅；绝对峰值上限不足以防止局部密度翻倍或翻数倍。添加前按原谱逐窗口计数，添加后以最终导出的谱面独立重算；空白段不应被规则填成无模型依据的连续按压。保护原有音符和长按，避免单个重音组突然膨胀，并把修正版作为可回退的试听候选。任务未指定具体上限时，先采取保守阈值，试听确认后才考虑推广；自动频谱分数不能替代节奏感反馈。

对需要消除微小多押错位的键盘谱，使用 `malody_studio/micro_chord_alignment.py` 的保守规则，覆盖非相邻轨道的双押、三押和四押。除单次偏移，还应识别围绕精确多押的短链与分成两组的重音；不能只检查两两相邻音符或固定宽度的整个链。以任务设定的阈值判断同一组，避开同轨近邻、跨越中的长按和有歧义的错落；只有另一轨道明确空闲时，才可将 tap 安全换轨后对齐，无法证明安全的情况应保留并记录。对要求舒适手感的谱面，使用 `malody_studio/lane_burden.py` 检查短时单轨负担；优先安全换轨，必要时有界删去 tap，不改原曲、模型音符时间或长按尾。有意要求 Jack 等重复型谱面时，不应套用与其谱型相冲突的舒适度上限。每次规则修正都须在独立版本或导入暂存区进行，并复检结构、平均 NPS、档位差和修正幂等性；保留原始版本供回退。重复导入时还须核对游戏目录里的实际谱面与曲包字节，不能仅凭导入标记或哈希字段判断它已是最新版。

生产任务默认 `retain_debug_artifacts=false`，不长期保留调试用中间 WAV 或大体积诊断文件。保留原曲、冻结参数、请求状态、不可变谱面、交付曲包及简要质量摘要；必要时为单曲单独开启诊断，不覆盖已采用版本。详见项目 [docs/storage.md](../../docs/storage.md)。

按用户选择的难度组成最终曲包；双难度只是常见示例，不是所有任务的固定要求。完成质量检查后，将每首选定包的路径和哈希写入显式交付清单，使用 `tools/import_chart_packs.py --dry-run` 独立回读；获准导入时指定本机实际 `--chart-dir`，不递归导入中间尝试版。默认原样导入，规则修正须与任务意图一致且单独启用、重新验收。项目 [docs/chart-quality.md](../../docs/chart-quality.md) 说明了检查指标、可选规则和导入流程。文件结构校验、自动手感规则、实际游戏导入和真人试玩分别报告，不能互相替代。

项目接口、引擎与曲包格式以 `README.md` 和当前服务健康信息为准；更改生成或后处理代码后运行相关测试，并对最终 MCZ 做独立回读。
