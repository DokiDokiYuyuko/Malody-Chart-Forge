# 多排键组合生成、统一命名与网页 4K 试玩

**项目：** 星轨谱面工坊 / Malody Chart Forge

**日期：** 2026-10-03

**状态：** 首版已实现；真实模型多排键推理与目标版 Malody 导入仍需实机验收

**数据目录：** `I:\model\malody`

**导出目标：** 保持现有旧版 Malody MCZ 兼容格式；新增桌面浏览器键盘试玩。

## 1. 目标与范围

用户希望一次为同一首歌生成多种排键、多个难度，下载或导入后能辨认每张谱面，并立即在网页中通过 D/F/J/K 试玩。

例如《天狼星的心脏》选择 Jack、Stream、Speed 和 Easy、Hard、Expert，点击一次生成，应得到 **3 × 3 = 9 张独立谱面**，共享歌曲音频和封面。选择多个排键的含义是分别生成这些版本，不是把多个风格同时加入一张谱面的模型条件。

首版保留单个模型选择，不新增多模型排列组合。保留已有上传、YouTube 导入、多曲队列、单档迭代、版本比较、主题及流速功能。网页试玩不需要账号、联网成绩、排行榜、皮肤市场或复杂 Mod，也不上传成绩至 Malody。

## 3. 需求一：多排键 × 多难度，一次生成

### 3.1 排键选择与术语

将单选下拉替换为带复选框的排键卡片或标签组。桌面端直接显示常用选项，小屏可展开；避免要求按住 Ctrl 的原生多选列表。保留六档难度卡片作为唯一的难度选择入口。

| 显示名称 | 稳定键 | 含义与实现依据 |
| --- | --- | --- |
| Balanced · 均衡 | `balanced` | 通用排键，沿用现有行为 |
| Jack · 连键 | `jackspeed` | 单轨重复击打倾向，兼容现有 Jackspeed 参数和模型条件 |
| Stream · 连打 | `stream` | 跨轨连续单键，减少无必要的同轨连键 |
| Speed · 速度 | `speed` | 快速交替、以单键或轻量双押为主；不改变歌曲播放速度和网页流速 |
| Jumpstream · 双押连打 | `jumpstream` | 连打中穿插双押 |
| Handstream · 多押连打 | `handstream` | 连打中穿插多押，受所选难度同刻上限约束 |
| Chordjack · 和弦连键 | `chordjack` | 连续重复和弦，与 Jack 单轨连键区分 |
| Stamina · 耐力 | `stamina` | 更持续的密集片段，保留真实音乐停顿 |
| Technical · 技巧 | `technical` | 节奏、切换和排键变化较多 |

Jack 与 Jackspeed 首版是同一选项的名称规范，不同时显示两个等价选择。用户所说的 Speed 新增为独立生成预设：已安装 MuG 特征配置没有独立 `speed` 特征，不得向模型发送虚构字段；可采用现有 Stream 条件与 Speed 后处理组合，V32 标签也须从已支持标签中选择。实际条件映射和后处理版本写入报告。

排键是生成倾向，不要求整首歌只有一种键型。例如 Easy Jack 仍需遵守 Easy 的同轨最短间隔，不能为了体现 Jack 而突破难度限制。

### 3.2 提交与设置

- 排键与难度均至少选一项；默认首次使用 Balanced，以及现有默认难度组合。旧偏好中的单个 `pattern` 自动迁移为一个元素的 `patterns`。
- 提交前显示摘要，例如“V32 · 3 种排键 × 3 档难度 = 9 张谱面”。排键全选、清空均有可见操作；清空后禁用提交并说明原因。
- 首版 9 种排键、6 档难度，单曲最多 54 张谱面；模型只选择一个。去除重复选项，拒绝未知键，服务端再次校验组合上限。
- 共用本次的模型采样参数、种子、长条目标和逐难度规则。高级设置允许逐排键覆盖倾向强度；该参数只显示给支持它的引擎。
- V32 自定义风格标签与当前排键条件逐项合并、去重、检查长度；任一排键超出标签限制时，在提交前指出具体排键，不能偷偷截断标签。
- 曲长继续受现有 5 秒至 10 分钟限制。多曲队列中，每首歌曲继承完整设置快照；界面同时显示歌曲数及最终谱面总数，避免把 20 首 × 54 张误认为 20 张。

### 3.3 生成策略与键型保留

一次导入和转换音频，一次准备封面，复用能复用的音频分析与模型输入特征。**每种排键生成一张独立母谱，再派生全部已选难度**。P 种排键、D 档难度默认执行 P 次母谱推理，而不是 P × D 次。

排键必须进入难度校准流程，不能只是文件改名。重构校准为“选择真实音乐事件与物量预算 → 按排键策略分配轨道 → 长条及冲突处理 → 结构校验与质检”。优先保留模型原有的有效键型片段；补充起音在满足约束时遵循该排键策略。

所有策略共用硬约束：同刻按键上限、滚动峰值、同轨间隔、长条占用、音乐静音与合法轨道。不得为了达到 Speed 的密度或 Jack 的重复次数，凭空在静音中加键或制造过密细分。

报告增加键型实测摘要：同轨重复比例、单押/双押/多押分布、连续片段长度及交替情况。在同样的母谱候选和难度约束下，用这些指标验证 Jack、Stream、Speed 的区别；真实歌曲无法形成明显区别时显示原因，不伪称成功。独立推理本身不保证每个输出一定不同。

### 3.4 队列、失败与恢复

- 一首歌曲仍是一条队列任务，内部包含排键母谱阶段和组合谱面阶段；默认沿用当前串行队列，不绕过已有并行验证条件。
- 进度显示当前排键、当前难度和已完成组合数；总体进度单调递增，不在切换排键时退回 0%。
- 某种排键推理失败时记录错误，继续其他排键。某张谱面结构校验失败时禁止导出该张，保留其他成功结果。
- 成功一部分时标记“部分完成”，显式列出缺失组合；可下载成功集合，但不可标成全部完成。全部失败时没有可下载曲包。
- 重试失败组合复用已完成排键缓存，不覆盖成功谱面。母谱缺失的排键才重新推理。取消等待任务、失败不阻塞后续歌曲、重启后暂停的规则继续生效。
- 每个排键及难度的种子由基础种子和稳定键经确定性散列派生，避免 Python 随机散列；改变选项顺序不改变同一组合的派生种子。记录模型版本、条件、排键策略版本和最终规则。

### 3.5 结果浏览与迭代

歌曲标题右侧新增排键选择，难度按钮只显示当前排键实际完成的档位。流速控件维持紧凑布局。切换排键、难度时，预览可保留音乐位置，统计、告警和下载链接必须同步切换。

曲包库继续每页 8 个歌曲级记录；一个含 54 张谱面的曲包不会扩成 54 张歌曲卡片。卡片显示“排键数量 / 谱面数量”，打开后按排键分组查看。

单档重生成和版本恢复升级为“当前排键的当前难度”。例如重生成 Stream Hard 只能改变这一张，不能覆盖 Jack Hard；各版本对应 MCZ 的内容和来源可追溯。

## 4. 需求二：文件名与游戏内谱面名

### 4.1 命名规则

单张谱面统一使用：

```text
{曲名}_{模型名}_{排键名}_{难度名}.mc
天狼星的心脏_Mapperatorinator-V32_Jack_Hard.mc
天狼星的心脏_Mapperatorinator-V32_Stream_Expert.mc
天狼星的心脏_MuG-Diffusion_Speed_Easy.mc
```

模型短名称固定为 `Mapperatorinator-V32`、`MuG-Diffusion`，精确权重版本与哈希放入报告。排键、难度显示名称采用上表英文名和 Easy～Lunatic，Lunatic 不附加“发狂”。

同一规则覆盖 MCZ 内的 `.mc` 文件名、单独下载文件名和游戏内版本名。`meta.song.title` 保留完整原始曲名，`meta.version` 使用“曲名 + 模型名 + 排键 + 难度”的显示形式；`meta.creator` 正确记录所用模型，避免 V32 被误标为 MuG。

单张曲包下载命名同一主干 `.mcz`；整曲组合包用集合名：

```text
天狼星的心脏_Mapperatorinator-V32_Jack+Stream+Speed_Easy+Hard+Expert.mcz
```

集合按固定排键顺序和难度顺序排列，不能用某一张的名字误称整包。超长集合名缩为 `3Patterns_3Difficulties` 等数量摘要，完整清单仍在网页和报告中。单谱版本下载追加 `_v2` 等版本后缀，避免丢失版本信息。

### 4.2 文件系统与兼容

- 曲名在显示元数据中保持原样；文件名副本按统一规则处理 Unicode、Windows 非法字符、控制字符、尾部点和空格、保留设备名。禁止路径穿越，不能把歌名中的 `/` 当目录。
- 限制文件名主干最多 120 个 UTF-16 单位；先缩短曲名，保留模型、排键、难度字段。同名或截断碰撞追加短 ID；内部 ID 不依赖文件名。
- 导出前核对最终完整路径长度；只在当前任务目录内创建文件，不重命名用户原音频，也不修改历史任务原文件。
- 保持 `.mcz` 的 `0/` 显式目录条目、UTF-8 谱面 JSON、`audio.ogg` 和可选 `background.jpg`，引用均是同目录相对文件名。
- 全部组合共享一份音频与背景；报告、中间缓存和模型文件不打入 MCZ。单谱 MCZ 也包含完整音频、图片及 `0/`。
- 打包从当前有效谱面清单读取，禁止直接遍历目录把历史被替换谱面一起打包。结构错误不会混入组合包。

## 5. 需求三：网页现场试玩 4K

### 5.1 用户流程与首版范围

完成生成或打开历史曲包 → 选择排键和难度 → 点击“现场试玩” → 音频准备完成 → 原谱面区域直接显示 3 / 2 / 1 倒计时 → D/F/J/K 打歌 → 结算 → 重试或返回预览。

试玩复用现有四轨视觉、主题和 1×～12×流速，判定线与音符下落方向保持一致。轨道从左到右固定为 D、F、J、K，键帽直接显示字母，并提供简短提示“左手 D/F，右手 J/K；长条需要按住”。键盘试玩首版面向桌面，不增加触屏打歌或键位编辑器。

必须支持单键、双押、多押和长条；生成器本来会输出长条，不能把长条静默改成单键。屏幕显示 Perfect、Great、Good、Miss、当前 Combo 和最大 Combo；击键对应轨道有短促高亮。结算展示四种判定数量、最大 Combo 和完整歌曲名称、模型、排键、难度。

首版不需要生命值、失败中途结束、复杂分数公式、官方等级或上传成绩；即使 Miss 很多也可打完。成绩不写回谱面文件，不改变生成报告。重试清空本次判定状态。

### 5.2 Normal 判定基准

试玩以 **Malody V PC / Key 4K / Normal（C Judge）** 为参考。当前可查到的 Gamerch 社区页面估计 C 判最佳窗口约为 ±36 ms，同时注明它不是官方确认数据；该数值只作为 Perfect 窗口参考，不表示已经精确复刻目标旧版或所有设备的判定。

当前网页判定配置集中维护在 `web/arcade.js`：Perfect ±36 ms、Great 至 ±72 ms、Good 至 ±108 ms，超过 Good 窗口记 Miss。Perfect 的 36 ms 是社区估值；Great、Good 边界是网页试玩规则，尚无官方依据。提前超过窗口的输入被忽略；过晚输入不能命中已 Miss 的音符。页面和成绩仅称“网页试玩”，不称 Malody 官方成绩或完整 Normal 复刻。

输入偏移可在 −250～+250 ms 调整并保存在本机浏览器。正值让输入按更早的歌曲时刻参与判定。窗口与偏移独立于预览流速；改变画面流速不会改变音频速度或判定边界。当前运行环境的具体 Malody 客户端构建号、手机补偿及 Pro Judge 差异没有完成实测，因此不能据此声称旧版客户端完全一致。

参考： [Gamerch 的 Malody 判定说明](https://gamerch.com/malody/318096)。

### 5.3 输入、选音符与 Combo

- 以 `KeyboardEvent.code` 的 `KeyD/KeyF/KeyJ/KeyK` 绑定物理键，分别处理 `keydown` 与 `keyup`。按键重复事件不能产生重复击打或靠长按自动完成 Jack。
- 一次真实按下最多判定该轨道的一颗音符；优先处理该轨道最早仍可判定的音符。错误轨道不能命中，空按不消耗其他轨道音符。
- 同一和弦各轨独立判定；一个键不能代打整组和弦。超过最晚有效窗口的音符自动 Miss，不依赖音乐 `timeupdate` 的低频更新。
- 普通音符 Perfect/Great/Good 增加 Combo，Miss 清零；结算统计不得重复计数。
- 长条首版采用明确的基础规则：头部通过按下判定，持续按住到尾部自动完成，也可在尾部窗口内松手；提前断开记 Miss；头尾各计一次判定与 Combo，中间没有自动加 Combo 的连续 tick。已 Miss 的同一判定单元不能重复扣分。
- 长条头 Miss 后进入失效状态；尾部按固定规则记 Miss，不能靠末尾补按获得成功。尾部释放容差使用网页试玩窗口；持续按住到尾部自动成功，完成后晚松手不会再追加判定。
- 上述长条与 Combo 是网页基础玩法定义；Normal 对齐指时间窗口，不将首版成绩称为 Malody 官方成绩。若目标游戏的长条结算方式不同，应记录差异，后续再对齐完整评分规则。

### 5.4 时间同步与基础偏移

预览当前使用 `<audio>.currentTime` 绘图，可继续保留；试玩增加统一音频时钟，建议用 Web Audio 解码已导出的 OGG，提前加载完成后才倒计时。通过音频时钟把音符时间、输入事件时刻和画面放到同一时间轴，不能靠每帧累加时间判断是否击中。

优先用 `AudioContext.getOutputTimestamp()` 估算音频输出时钟与 `performance` 时钟的映射；不支持时使用明确的降级时钟和手动偏移。该 API 提供音频设备正在输出的帧位置及对应性能时间估计，仍不等于能测量所有键盘、蓝牙和显示延迟。[MDN 文档](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/getOutputTimestamp)

保留一个基础“输入偏移”设置，默认 0 ms，范围 −250～+250 ms，步长 1 ms。规定正值将输入视为更早：`判定输入时间 = 映射后的歌曲时间 − 输入偏移`。保存到本浏览器偏好；不改 MCZ 时间戳。设置页给出简单解释，避免和视觉流速混淆。

绘制只负责显示；判定按统一时钟和输入事件时间戳执行。同一段按键事件在不同帧率下应得到相同判定。不要把晚处理事件的回调时间当作真实按下时间，也不要让一个渲染卡顿自动覆盖已到达的有效输入。

试玩使用最终导出的谱面对应的规范化音符，正确处理变 BPM、起始音频 offset 和长条尾部；不能只根据平均 BPM 重新换算。预览和试玩共用音符加载器，确保网页试玩与下载的 MC 是同一版。

10 分钟立体声音频解码为浮点 PCM 约需 202 MiB，不把试玩当成零内存开销；仅维护一份活跃歌曲缓冲，退出/换曲释放旧资源。加载失败保留曲包下载和普通预览入口，并说明具体原因。

### 5.5 交互状态与失焦

状态为 `idle → loading → countdown → playing → finished`，播放中可进入 `paused`，退出回 `idle`。倒计时阶段不产生判定，音乐开头的音符必须有完整来音时间。

- 预览点击播放/暂停的行为继续保留；进入试玩后点击轨道不再误触预览暂停。空格或 Esc 暂停，提供可见的继续、重试、退出按钮。
- 开始由用户点击触发音频权限；音频加载或浏览器拒绝播放时不能空跑判定。
- 失去窗口焦点、切换标签页或浏览器隐藏时自动暂停，清理按键状态，不让回到页面后出现卡住的键或一串 Miss。
- 暂停时冻结音乐位置与判定。继续采用倒计时；活动长条在继续前提示重新按住对应键，播放恢复时未重新按住才判定断开，暂停本身不制造 Miss。
- 正式试玩期间锁定拖动时间轴、排键/难度切换与版本恢复；退出试玩后可恢复。流速仍可调整，仅改变画面，不改变判定窗口或歌曲播放速度。
- 仅在试玩激活且焦点不在输入框、选择控件或弹窗中时接管 DFJK/空格。退出后恢复页面原快捷键。
- 试玩采用专注布局，统计面板换成本次判定与 Combo；既有主题和四轨不同颜色继续使用。低动效偏好关闭夸张特效；打歌期间暂停鼠标流星与不必要的装饰动画。

## 6. 数据模型与接口设计

### 6.1 独立谱面标识

使用稳定 `chart_id = pattern + "--" + difficulty`，例如 `jackspeed--hard`、`stream--hard`。独立字段保留，不让页面从文件名推断排键或难度。

```json
{
  "schema_version": 3,
  "options": {
    "engine": "v32",
    "patterns": ["jackspeed", "stream", "speed"],
    "difficulties": ["easy", "hard", "expert"],
    "seed": 20261001
  },
  "charts": [
    {
      "chart_id": "stream--hard",
      "pattern": "stream",
      "difficulty": "hard",
      "status": "completed",
      "filename": "天狼星的心脏_Mapperatorinator-V32_Stream_Hard.mc",
      "active_version": 1,
      "preview_key": "stream--hard"
    }
  ]
}
```

状态、统计、质检告警、预览和版本均绑定 `chart_id`。生成缓存按排键隔离，例如 `cache/stream/generation-cache.json`；V32 分段时轴也按排键保存。每档参数与排键策略保存在对应版本记录中。

### 6.2 拟新增及扩展接口

| 接口 | 设计 |
| --- | --- |
| 现有生成、上传及批量接口 | 接受 `patterns` 数组；旧 `pattern` 作为单元素兼容输入；两者同时提供且矛盾时拒绝 |
| `GET /api/jobs/{id}` | 增加 `charts`、组合进度、失败组合、部分完成状态，保留旧字段 |
| `GET /api/jobs/{id}/charts/{chart_id}` | 返回该版本的规范化音符、音频引用、模型/排键/难度与版本身份 |
| `GET /api/jobs/{id}/charts/{chart_id}/download` | 单张 MC 下载；支持明确选择单张 MCZ |
| `POST /api/jobs/{id}/charts/{chart_id}/regenerate` | 指定排键与难度的局部重生成，复用该排键缓存 |
| `GET /api/jobs/{id}/charts/{chart_id}/versions` | 比较对应谱面的版本 |
| `POST /api/jobs/{id}/charts/{chart_id}/restore` | 恢复对应谱面版本，其余组合不变 |
| 现有整曲下载接口 | 返回全部成功组合的 MCZ，下载文件名采用集合命名 |

试玩判定与本次成绩在浏览器执行，不逐键请求服务端。服务端只负责合法任务、谱面版本和音频资源读取。

### 6.3 历史兼容

读取旧 `job.json` 时，将旧 `pattern` 或缺省 Balanced 映射为单排键，保留原难度文件名和版本历史。旧 `normal` 难度别名继续映射 Medium，与 Normal 判定配置分开。

旧的按难度接口可在单排键任务上继续工作；多排键任务必须指定 `chart_id`，旧接口返回明确的歧义错误，不能随机操作第一个同名难度。旧 `previews` 字段保留一个确定的默认排键视图，新的网页优先使用组合数据。

无母谱缓存的旧曲包可以预览和试玩，但单档迭代仍提示重新生成。新的规范命名只作用于新导出和新版本，不批量破坏用户已下载文件。

## 7. 实施顺序

1. **组合数据与命名：** 抽离谱面 ID、命名和任务 schema；升级生成参数、打包与历史读取；先以模拟母谱完成组合端到端测试。
2. **排键生成与保留：** 各排键独立条件和缓存；重构难度校准以保留排键；支持部分完成及失败重试，核对母谱调用次数。
3. **选择与结果页面：** 多选面板、组合摘要、排键切换、曲包数量、组合版本比较；继续保持桌面紧凑布局。
4. **判定基准与引擎：** 核验 Malody Normal 数值，建立独立判定模块；用模拟时钟完成单键、和弦、连键、长条、Miss 与 Combo 测试。
5. **网页试玩：** 音频时钟、DFJK、倒计时、暂停失焦、结算和主题集成；最后用实际歌曲试听与键盘试玩验收。

上述主要流程已经落地：多排键母谱与难度组合、统一文件命名、按排键浏览、单档版本、单谱 MCZ，以及 DFJK 网页试玩。自动化测试通过；真实 MuG/V32 多排键 GPU 生成和目标版 Malody 实际导入仍需用目标歌曲完成验收。

## 8. 验收与测试清单

| 类别 | 必须通过的检查 |
| --- | --- |
| 排列组合 | 3 排键 × 3 难度输出恰好 9 个独立 ID 和文件；默认 9 × 6 不超过 54；空选、重复、未知键及超限可控 |
| 推理复用 | 3 排键执行 3 次母谱生成；同排键不同难度不重复推理；同曲只导入/转换/准备图片一次 |
| 键型区别 | 受控候选下 Jack 同轨重复比 Stream 高，Stream 以跨轨单押为主，Speed 保留快速交替；策略不突破逐档硬约束；不能仅改名或做一次全局换轨 |
| 真实模型 | MuG、V32 分别完成多排键端到端生成；明确记录耗时和实测差异，不承诺多个排键与单排键同耗时 |
| 失败隔离 | 一个排键失败仍能生成其余结果；只导出结构校验通过的谱面；部分完成摘要和失败重试正确 |
| 文件与 MCZ | Unicode 曲名、非法字符、超长名、同名碰撞正确；共享音频/背景、显式 `0/`、文件引用及 ZIP 校验正确；无旧版残留谱面 |
| 实际导入 | 至少对多排键多难度曲包在目标旧版 Malody 实际导入，核对歌曲分组、版本名称、音频与图片；不能用文件校验代替游戏导入证据 |
| 定向迭代 | 只改 Stream Hard；Jack Hard 及其余文件哈希不变；恢复版本后预览、试玩、下载一致 |
| 历史兼容 | 单排键旧任务、`normal` 难度别名、缺缓存任务均可读取；网页偏好迁移不丢参数 |
| 判定边界 | 对每个核验窗口的边界、边界内外各 1 ms 和提前/延后输入测试；保存 Normal 来源及版本 |
| 键盘输入 | DFJK 四轨、和弦、同轨连键、长按重复抑制、错误轨道、输入框焦点均正确 |
| 长条与计数 | 头部、正常释放、提前断开、过晚释放、头 Miss、暂停持键；无重复判定，四种统计之和等于本次应判定单元数 |
| 音画同步 | 单 BPM、变 BPM、音频 offset 均按导出时间轴；30/60/120 FPS 下相同事件得出相同结果；卡顿不使有效输入按回调时刻变 Miss |
| 交互 | 加载失败、音频权限失败、失焦暂停、继续、重试、退出、结束结算；试玩锁定定位与切谱，退出后原预览可用 |
| 视觉与性能 | 常见笔记本与宽屏无横向溢出；四轨颜色不同、键位清晰、1～12×有效；退出和换曲不残留监听器、动画或音频缓冲 |

关键用户场景验收：以《天狼星的心脏》选择 Jack / Stream / Speed 和 Easy / Hard / Expert，一次提交；能逐张切换、下载名称明确的组合曲包，并用 DFJK 从头到尾试玩任一张，看到四类判定与 Combo。

### 按键音、长条与中央反馈（2026-10-03）

- 设置中加入 6 种 Kenney Interface Sounds 按键音，提供试听、0–100% 音量与开关；默认清脆点击、30% 音量。来源和 CC0 授权保存于 `web/assets/keysounds/`。
