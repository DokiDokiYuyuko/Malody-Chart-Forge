# 高级分段制谱与 Agent 修谱

状态：2026-10-04 操作流程重设计已集成，包括完整音乐空白起步、四模式常驻时间轴、独立音频分离、建议划段原子应用、批量候选和划段撤销。实际模型、音频拼接与浏览器验收见 [高级台重设计验收](advanced-workflow-redesign-validation.md)。云端能力由用户 API 连接检查确认；实际曲感与 20 组人工 A/B 评价单独记录，自动测试不代替这项验收。

## 产品流程

导入音乐 → 划分片段 → 分段生成 → 试听、Autoplay 或 DFJK 试玩 → 局部重生成 / Agent 候选 → 人工选择版本 → 拼接预览 → 导出经典 Malody MCZ。

高级台位于顶部「高级制谱」，普通工作台保留原有流程。常驻原曲时间轴、左侧片段、中间四轨和右侧版本摘要；四个模式仅切换右侧操作面板，原曲时间轴与谱面始终可见；详细参数按需展开。手机纵向排列，桌面固定视口，侧面板独立滚动。

| 已确定方向 | 实施规则 |
|---|---|
| 导出 | 只拼接选中的音频与谱面区间，按原曲时间排序 |
| 音频过渡 | 不连续切口采用约 5 ms 淡出 / 淡入；不重叠，不插入间隔，不改变采样数 |
| 多难度 | 默认各档独立模型输出；可选母谱快速分层 |
| 玩法 | 手机四指、键盘 4K 分开保存评审目标 |
| 人工修谱 | 参数调整、局部重生成、版本选择；首版不建设完整音符编辑器 |
| Agent | 用户自带修谱 API，可选听音 API；显示发送范围；手动应用候选 |
| 兼容 | 旧版 Malody，`0/` + `audio.ogg` + MC + 背景图 |

MuG 是扩散制谱模型；Mapperatorinator V32 是音频条件事件序列模型。现有六档快速流程会重新选择起音和分配轨道，可能弱化母谱意图；独立策略保留有效模型原谱，规则处理另存候选。已有初稿属于条件修订，用户认可的明确示例才作为 few-shot 参考。

## 时间、项目与版本

### 三个时间基准

1. 原曲时间：划段、稳定事件 ID、质检与 Agent 的证据。
2. 模型输入时间：MuG 的前后 4 秒上下文与输入原点；V32 的原曲起止毫秒和原生上下文。
3. 成品时间：移除未选区间、按采样数累计映射，并统一加入准备时间。

原音频保存原始文件及一次解码的 44.1 kHz 双声道 PCM。片段范围保存整数采样位置，采用 `[start_sample, end_sample)`。允许相接、不允许重叠，每段至少 250 ms。波形支持缩放、移动、鼠标 / 触摸划段、两端调整、数值输入、用播放位置设置端点以及下一段。节拍吸附默认关闭；不可靠节拍只作参考。

项目保存源音频哈希、玩法、排键 × 难度清单、设置模板、节拍参考及 BPM 时间锚点。片段保存范围、名称、纳入拼接状态、覆盖设置、候选版本列表和已选版本引用。提交任务保存完整输入快照，模板后续变化不会改写既有版本。

修改范围清空当前版本引用，保留旧候选并标记范围过期。拆分为两段或三段时按音符头的半开区间归属继承版本，保留原有长条尾部与来源信息。移除片段不删除不可变版本文件。

生成首次可以成为当前版本。之后原谱、快速分层、规则候选、Agent 修订均保留独立文件；点击「使用这一版」才替换。评审状态「未评 / 可用 / 待改」与原因绑定版本，音符内容不可变，评审决定记录在项目清单。

### 生成策略与参数

| 策略 | 模型调用 | 原谱与规则 |
|---|---|---|
| 独立生成（默认） | 每个片段 × 排键 × 难度单独条件输出；同任务复用加载和音频特征 | 保留有效原始音符；不默认以 NPS 重新排键 |
| 母谱快速分层 | 每个片段 × 排键一张母谱 | 复用真实母谱、起音候选、上下文和已记录设置，分层结果另存 |

两模型分别设置六档条件，初值 `2.0 / 3.3 / 4.6 / 5.9 / 7.2 / 8.0`。这不是跨模型等价难度、目标 NPS 或 Malody 等级。采样参数、步数、风格标签、长条比例、种子、逐档平均密度 / 峰值 / 同刻上限 / 同轨间隔 / 长条上限均保留。项目设置与片段覆盖明确区分。

默认重生成新种子，可固定种子复现；每种排键和档位通过确定性派生种子隔离。只重生成当前组合不改变其他组合。快速规则处理复用母谱起音缓存；更改采样设置需要重新推理。任务进入原有 FIFO 队列，默认串行，遵守原有双任务硬件门槛；重启后暂停或中断，不自动运行。

结构无效模型音符的移除须保留诊断与原模型缓存；不能将清理后的结果宣称为未经处理的全部输出。上下文内、目标范围外的音符不属于片段；外部头部的长条排除并记录。

### 拼接边界

| 情况 | 处理 |
|---|---|
| 跳过部分原曲 | 移除相同音频采样与时间；后续音符和 BPM 按同一映射前移 |
| 音符位于端点 | 半开区间保留一次 |
| 不连续长条 | 裁到切口，报告裁尾；不跨越被删区间 |
| 连续长条 | 沿连续来源区间保留，检查后续占轨；冲突阻止导出，不能静默删键 |
| 裁尾不足 100 ms | 转普通音符并记录 |
| 空谱片段 | 可保存；最终每张成品至少一个音符；不受旧版八音符下限限制 |
| 缺失组合 | 列出缺失片段，不用空谱补齐；只导出完整组合 |
| 变 BPM / 非整拍切口 | 根据成品毫秒重新积分拍坐标，不相加片段拍零 |

PCM 完成所有裁剪和拼接后只编码一次 Vorbis。编码后检查采样数，MC 回读头尾时间误差小于 1 ms。准备时间默认 1.5 秒，可设 0–3 秒，音频和音符一致平移。成品可试听、Autoplay 和试玩，再下载曲包。命名为曲名（剪辑版）+模型+排键+难度；混合模型以 Mixed-Models 标识，报告保留逐段来源。母谱、密钥和审谱文件不打入曲包。

## Agent 证据、工具与应用

本地缓存包含波形 / RMS、三频段正谱通量、起音锚点、估计节拍及不确定性、HPSS 成分、频谱、音符头尾与占轨。HPSS 是谐波 / 打击成分参考，不是准确的人声 / 鼓 / 贝斯分轨。

默认核心窗口 12 秒，前后各 2 秒只读上下文；超过 256 音符头继续拆分。跨界长条和邻近占轨一并读取。界面明确显示原曲分析范围及实际送往听音模型的范围。

工具：`get_project_constraints`、`get_chart_events`、`get_audio_features`、`get_audio_snippet`、`get_alignment_plot`、`compute_quality`、`submit_patch_candidate`、`compare_candidate`。模型只能使用这些边界内工具，没有任意路径 / 脚本访问。

后端显式加载 [审谱 Skill](../skills/malody-chart-review/SKILL.md)，记录版本。用户评为可用的版本可手动加入示例库，每次最多三个匹配示例；未认可模型输出不自动当成优质例子。

### API 与密钥

设置包含必填修谱模型、可选听音模型，分别配置基础地址、模型、密钥和 Responses / Chat Completions 接口。连接检查实际测试工具响应；无工具能力只做一次性分析。听音通过 Chat Completions WAV 输入进行实测，不由模型名称推断。GPT‑6 Astra 的文本 / 图像 / 工具能力不能被误认为原始音频输入能力。

会话配置仅存后端内存。勾选保存时用 Windows 用户 DPAPI 加密写入 `private/agent-config.dpapi`，目录已忽略；密钥不返回前端、不入浏览器持久偏好、不入报告。请求无自动收费重试；每窗口最多两轮修订、八次工具调用。显示请求与 token，未知价格不显示臆测金额。服务重启将运行评审标为中断，不自动重发。

### 修改候选

补丁包含 base_revision、核心范围、分组 ID、理由、证据引用和 add / delete / update 操作。新增 / 移时 / 修改尾部须引用本地音频或节拍锚点并在 1 ms 内匹配。未知音符、重复操作、只读范围修改、非法长条、同轨冲突和基础版本过期均拒绝。依赖操作按组一起应用。

候选验证不自动改变谱面。双四轨用同一原曲音频时钟，窄屏 A/B 切换；标记新增、删除、移时 / 换轨 / 长条变化，点击建议定位。用户选择组并应用后创建 Agent 版本、激活、重新计算质检；不再经过旧密度重排流程。BPM / 全局偏移只作为诊断，首版不让 Agent 更改。

## 数据与接口

高级项目位于 `outputs/advanced/<project-id>/`；不可变 `revisions/*.json`、原曲、音频特征、拼接 `assemblies/<id>/`、评审 `reviews/*.json` 与人工 `evaluations.json` 分开。项目清单采用原子替换及乐观版本检查；模型仍使用已有项目本地权重。队列任务和母谱位于 `outputs/<job-id>/`。

`/api/advanced/projects` 提供上传、历史曲包 / 已下载音乐导入、片段增改删 / 拆分、生成、任务状态、版本读取 / 选择 / 评审、规则候选、成品拼接 / 预览 / 下载、Agent 分析 / 候选应用、示例库和 A/B 记录。`/api/advanced/agent` 提供配置与能力检查。普通生成和下载契约不变。

历史 MCZ / 曲包导入为完整音频片段，来源为 `imported_final`；缺少原谱缓存时明确 `raw_available=false`。后续仍可拆分、规则处理和 Agent 修订，不能伪称导入了原始模型输出。

## 实施与验收

1. 时间与项目：PCM、划段、拆分、快照、不可变版本、时间映射。
2. 生成与导出：两引擎策略、队列、局部迭代、接缝、成品试听与 MCZ。
3. Agent：特征 / 时序工具、接口与密钥、Skill、补丁校验、同步比較、人工应用与质量评价。

自动验收涵盖连续 / 不连续、非整拍、变 BPM、短片段、空谱、长条跨界、时间回读、缺失组合、候选保留、设置快照、冲突版本、未知 ID、重复操作、越界、非法长条、接口不完整和密钥加密。浏览器验收覆盖实际音频与导入 / 划段 / 候选 / 比较 / 试玩 / 成品导出。

质量评价必须使用低 BPM、快速电子乐、人声复杂段、持续音、变 BPM、接缝六类真实片段，记录至少 20 组人工 A/B。比较结构合法、节奏贴合、排键意图、难度一致性和接缝体验，保留接受 / 拒绝原因，手机 / 键盘分开。质量告警不合成官方等级；“N 分音符”和“拍的分数”换算须正确，不能把切分、三连音或高密度本身当作错误。

[自动测试](../tests/test_advanced.py)与[质量评价记录工具](../tools/advanced_evaluation.py)提供可复核记录。文件校验和实际 Malody 导入 / 手感分别验收，未实测的项目不能冒充通过。

## 常驻时间轴工作台重构（2026-10-04，已集成）

### 产品与交互

正式页面已替换七步大弹窗和旧 DOM 搬动逻辑，使用最终组件提供四个模式：

| 模式 | 主要操作 | 次要信息 |
|---|---|---|
| 准备音乐 | 导入完整音乐，明确选择制谱输入 | 分离版本、试听切换、局部试分离、任务进度 |
| 划段 | 分析建议 → 图上确认 → 一次应用真实片段 | 精确时间、手动拆分、节拍参考、整次撤销 |
| 生成 | 多选片段，选择输入与组合，一次提交 | 模型参数、片段覆盖项、缓存复用、失败与重试 |
| 选谱与导出 | 比较新方案、手动采用、成品预览 | 原始声部、历史版本、规则、融合、Agent、评审 |

完整音乐无需先生成谱面。空项目及缺失组合显示空轨道，不拿其他片段的音符填充。模式切换不会取消后台任务、偷偷采用谱面或改变试听音轨。

时间轴显示实际片段、待确认建议、原曲波形、节奏活动、BPM 参考与播放位置。已有边界标为保留；建议能拖动、合并，应用前明确显示实际片段变化。分析区间不冒充已创建片段，也不冒称识别出了主歌、副歌。BPM 接受与划段应用分别操作。

### 数据与 API

- `POST /api/advanced/projects/{pid}/segmentation-preview` 验证原曲身份、采样范围、最短长度、人工边界和纳入状态，保存不可变划段草稿，不改项目清单。
- `POST /api/advanced/projects/{pid}/segmentation-apply` 校验项目版本与草稿版本，禁止修改尚在生成的受影响片段；一次提交所有新片段和继承引用。磁盘失败不会留下半套清单。
- 已采用和候选版本按半开区间的音符头归属继承，保留跨界尾部、原曲时刻与父版本来源；派生版本重新评审。原布局存入独立历史，可整次撤销。
- `POST /api/advanced/projects/{pid}/generation-batches` 冻结所选片段、组合、设置与输入来源。独立任务使用既有调度和并行门槛，不创建占着 GPU 等子任务的父任务。请求 ID 支持重复提交恢复，提交前完成全部预检。
- 批量结果不自动采用，两路输入默认产出融合候选。`POST /select-many` 在一次清单写入中手动批量采用。
- `GET /section-plans` 恢复已完成的分析，不因打开新音乐自动开始耗时分析。`GET /layouts` 查看原布局和不可变谱面历史。
- 原有单曲、音频、任务、曲包和下载接口保持兼容；旧任务缺少执行计数时不补造数据。

统一前端状态保存项目、模式、片段、组合、候选、音轨、草稿、播放位置与成品；异步响应核对上下文。分离、模型推理和 Agent 评审分别展示，云端任务不因刷新自动重发收费请求。

### 候选、播放与导出

A/B 默认单谱面切换，同一音乐位置；并排可选。新增、删除、移时、换轨和长条调整可标记并定位。规则、声部融合和 Agent 都产生候选，不直接覆盖采用版。只有一个版本时不出现 A/B 评价。

试听原曲、人声、伴奏和剪辑成品明确标识；切换保留位置，只使用一个音乐源。加载期间的 Esc 或失焦暂停不会在加载完成后被旧请求撤销。试玩与 Autoplay 复用现有判定、长条、Combo、按键音和结算。

成品预览列出保留片段、时长、接缝与缺失组合，只使用已采用版本。原曲采样时钟保持不变；剪辑成品用独立映射，准备时间、移除区间、长条接缝与 MCZ 兼容规则继续沿用。

### 视觉与验收

青色强调、少量粉色、细切角和实底面板。中文使用微软雅黑 UI，时间与数字使用 Bahnschrift；正文 14–15 px，辅助信息至少 13 px，主要按钮至少 40 px。应用划段、开始生成和成品预览固定在面板底部。

桌面固定视口、侧面板内部滚动，时间轴约 164 px，剩余高度归谱面。1366×768、1440×900、1920×1080 的谱面与操作面板底部对齐；390 px 纵向排列，五种主题保留。
