# Malody Chart Forge 用户体验优化需求与实施方案

**状态：** 第一轮实现与自动化验证完成
**适用目标：** 旧版 Malody、手机四指 4K、本地 Windows 制谱
**范围：** 降低首次安装和日常制谱的操作成本，提升谱面预览与曲包管理体验。不涉及增加模型或训练新模型。

## 1. 背景与目标

当前网页已经支持本地上传、YouTube 搜索与导入、六档难度、生成进度、四轨预览、统计报告和曲包分页。工作流和功能已经具备，但新用户仍要理解 NPS、引擎参数与多组细调规则；模型没有准备好时，界面给出的排查线索有限；首次安装需要手动创建多个 Python 环境并逐个下载权重；曲包记录缺少直接管理动作；预览区的固定三秒视窗和当前绘制样式难以清楚呈现谱面变化。

本方案希望让新用户无需先读懂模型术语，也能完成“准备环境 → 选歌 → 选难度 → 生成 → 听看检查 → 下载导入”；熟悉参数的用户仍可进入自定义设置。安装、诊断、预览和记录管理均在本机完成。

## 2. 设计原则

- 每个页面只突出一个主要动作；次要参数按需展开。
- 同一个难度只有一个生成选择入口。细调控件只用于修改所选档位的参数。
- 模型状态说明具体问题和下一步操作，不以笼统的“准备中”代替诊断。
- 安装程序可重复运行、支持中断续装，并对模型文件执行版本和哈希校验。
- 预览流速只改变预览画面，不修改 MCZ 内的谱面时间或 Malody 游戏设置。
- 用户音乐和曲包留在项目目录；删除动作清楚显示会释放哪些本地数据。

## 3. 需求

### 3.1 难度设置与推荐/自定义模式（优先级 P0）

1. Easy、Medium、Hard、Expert、Master、Lunatic 六个卡片是唯一的难度选择入口。每张卡片清楚显示“是否生成”及易懂的强度说明。
2. 将“按难度细调谱面规则”改为“细调已选难度的规则”，展开后只展示已勾选的档位。取消勾选时隐藏该档细节，但保留用户刚才输入的参数，重新勾选后恢复。
3. 默认展示“推荐设置”：选歌、六档选择、长条比例和必要的谱面类型。NPS 解释为“每秒音符数（NPS）”；模型温度、采样步数、CFG、标签和逐档规则放入“自定义设置”。
4. “推荐设置”使用经项目验证的默认值，不自动改变用户已选引擎。切换模式不清空参数。
5. 自定义设置中的模型参考难度明确标记为“模型生成母谱的输入条件”，并与最终 Malody 档位区分。
6. 保存难度、引擎、谱面类型、流速等非音频偏好。提供“恢复推荐默认值”。不在浏览器存储中保存音频二进制或密钥。

**验收：** 难度卡片和细调行之间有明确对应关系；只生成勾选档位；未勾选行不占空间；切换推荐/自定义或刷新页面后，已保存的非文件设置按预期恢复；用户可一键恢复默认值。

### 3.2 模型就绪诊断和一键配置（优先级 P0）

提供 `一键配置环境.bat` 作为入口，并由项目内 PowerShell 脚本执行可读、可重试的安装步骤。至少支持选择 MuG、V32 或两者；设置环境和模型权重目录统一位于项目根目录。

安装脚本按阶段执行：

1. **预检：** Windows 版本、Python 3.12 x64、Git、磁盘空间、NVIDIA 驱动/GPU、现存环境和权重。
2. **依赖：** 安装主环境；按需建立 V32 独立环境；严格使用项目锁文件。检查 CUDA 可见性，不以“安装成功”误报 GPU 可用。
3. **模型：** 固定模型版本和来源，采用续传/重试，下载完成后核对 SHA-256；已有校验通过的文件直接复用，损坏或校验不符时停止该模型并说明处理方式。
4. **验证：** 运行依赖导入、模型文件、显卡与引擎就绪检查。可以选择执行短音频冒烟生成；冒烟测试须清楚说明会读取哪段本地音频并将输出保存在哪里。
5. **结果：** 展示完成、跳过或失败的阶段；失败时提供日志位置和可复制的下一步命令。日志不得记录代理密码、令牌或其他凭据。

脚本应幂等且无需管理员权限：重复运行不会重装已通过校验的环境与模型；可跳过模型、只修复某个阶段，也可在网络中断后续装。MuG 下载开始前应提示并要求确认上游的非商业使用限制；V32 与 MuG 继续使用隔离环境和独立就绪状态。启动网页保持独立于安装脚本，用户可在安装结束时选择立即启动。

**大陆网络配置：**

- 支持用户选择或配置 pip 镜像、Hugging Face 端点及 HTTP/HTTPS 代理；脚本同时兼容已有的 `PIP_INDEX_URL`、`HF_ENDPOINT` 和代理环境变量。
- 保留锁文件中的 PyTorch CUDA 官方 wheel 源；普通 Python 包镜像切换不得悄悄改变 PyTorch/CUDA 版本。
- 默认源不可达时提供清楚的网络错误和切换入口；不将未经校验的模型镜像写死为唯一来源，也不因镜像可达而跳过哈希校验。
- 大模型下载显示进度，支持分段续传、超时重试和校验失败后清理无效临时文件。Git 子模块安装允许用户配置代理。
- 代理配置由用户显式提供，不自动探测、配置或绕过网络限制；退出脚本后不将临时代理凭据写入项目文件。

现有 `/api/health` 把 MuG 是否可用作为全局 `ready`，需要改成按**当前所选引擎**判断是否可生成；否则 V32 单独安装完成时按钮仍可能禁用。状态响应应分别报告每个引擎的权重、Python 环境、CUDA 和版本检查，并附带稳定的错误代码及本地化说明。网页可显示“可生成”“缺少权重”“环境未安装”“GPU 不可用”“版本不匹配”等状态及对应安装指引。

**验收：** 干净目录可按所选引擎完成配置；第二次运行跳过完整且校验通过的步骤；下载中断后能续传；哈希错误不会启用模型；MuG/V32 单独安装时各自的按钮状态正确；网络源或代理配置错误时可定位；安装不要求管理员权限，凭据不落盘。

### 3.3 预览重做与流速控制（优先级 P0）

当前预览以 Canvas 绘制四条轨道，固定使用 3000 ms 视窗，音符高度和播放控制有限。重做目标是让用户能看清音符、和弦、长条和节奏，并能快速定位到音乐片段。

1. 提供“专注预览”模式：扩大四轨区域并收起设置/统计侧栏；普通模式也应更充分利用窗口高度。桌面默认使用约 65–75% 的可用视口高度，并允许用户拖动或点击切换放大；小屏幕下不产生横向滚动。
2. 采用经典 4K 下落式视觉层次：四条清晰分隔的轨道、顶部来音区域、判定线、明显的单键与和弦、持续可辨的长条、当前播放位置。图形使用项目自绘素材，不依赖 Malody 未授权图标或纹理。
3. 增加“预览流速”控件，默认 1.0×，范围 1×–8×，提供 1×、2×、4×、8×快捷档；音符间距按同轨事件自适应，避免高速段糊成条带。界面说明该值只影响网页预览，不写入曲包，也不改变游戏内滚速。
4. 预览和音频播放、拖动定位、波形位置保持同步；暂停后画面停止，继续播放后无跳帧式大幅漂移。切换难度不重置播放位置。
5. 提供键盘操作：空格播放/暂停、方向键小幅定位、流速控件可键盘调整；按钮和当前状态有可读标签。
6. 统计面板与预览联动，清楚解释音符数、平均每秒音符数、滚动一秒峰值和长条数；展示难度间密度递进，异常差距给出解释。

**验收：** 390 px 手机宽度、常见笔记本和大屏均可操作，无横向溢出；专注模式明显扩大谱面；改变预览流速会改变音符视觉下落速度，但音频时间、MC 文件和生成报告不变；长条长度、判定线位置与音频时间一致；播放/暂停/定位经过手动回归。

### 3.4 曲包库管理（优先级 P1）

在现有搜索和分页基础上增加可直接完成的管理动作：

- 每个完成的曲包卡片提供“下载 MCZ”和“打开预览”；失败或中断的任务提供查看原因和重试入口。
- 提供“按此设置再生成”，恢复该任务保存的非敏感参数，允许修改后提交。复用任务包中已保存的处理后音频，避免要求用户再次找文件；界面应标注来源音乐与本次设置。
- 支持按标题搜索、按创建时间排序，并按状态、引擎和难度筛选；保留分页，筛选后回到第一页。
- 提供逐项删除和清理失败任务。删除前说明将删除的曲包、报告和本地音频；提供二次确认。MVP 暂不提供不可逆的批量删除。
- 显示输出目录、下载音乐库及总计占用空间；接近用户设定阈值时提示清理。空间数据只统计项目目录。
- 后端删除和重生成只接受已存在的任务 ID，校验目标路径位于项目 `outputs/` 内，禁止通过请求参数指定任意文件路径。

**验收：** 曲包卡片可直接下载；相同参数可再次生成并允许修改；删除后列表、任务状态和实际磁盘占用一致；无法删除正在运行的任务；筛选与分页正确；服务重启后历史记录仍可浏览，进行中的旧任务明确标记为中断并提供重试。

## 4. 信息架构建议

1. **制谱工作台：** 选音乐 → 推荐难度设置 → 生成。主按钮固定可见，按钮旁显示当前模型是否可用。
2. **自定义设置：** 按“难度规则”“谱面倾向”“模型参数”分组，默认折叠；每项采用简短解释、推荐值和恢复默认值。
3. **预览：** 播放控制、预览流速、波形定位、难度切换位于预览区附近；专注模式隐藏非必要信息。
4. **我的曲包：** 搜索与筛选 → 卡片预览/下载/再生成/删除；顶部显示结果数量与本地占用空间。
5. **首次配置：** 独立的安装向导/诊断页面展示总进度、当前步骤、来源、验证结果与日志入口，不把配置命令混入日常制谱面板。

## 5. 实施方案与阶段

### 阶段 A：难度与设置简化

调整 `web/index.html`、`web/app.js`、`web/style.css`：加入推荐/自定义视图；细调规则按所选档位动态显示；用 localStorage 保存带版本号的非敏感参数；添加恢复默认值。定义推荐默认值的单一来源，避免 HTML、前端和后端的默认值漂移。

### 阶段 B：安装与就绪诊断

新增 `一键配置环境.bat` 和 `setup.ps1`；扩展下载脚本支持可配置源、失败续传、预检和阶段性日志；扩展 `/api/health` 的引擎诊断。让启动器发现环境缺失时引导运行安装脚本，而不是只抛出异常。测试时通过临时网络错误和哈希错误场景验证安全失败。

### 阶段 C：预览重做

把 Canvas 中固定 `windowMs` 改为可配置的像素/秒滚速和视窗；加入专注模式及放大控制；优化长条、判定线、和弦与键型颜色。把绘制、缩放、播放定位拆为小模块，减少目前每帧重建轨道背景的开销；对高 DPI、浏览器缩放、隐藏标签页和暂停恢复进行处理。

### 阶段 D：曲包库管理

扩展 `/api/history` 查询条件，新增安全的下载/删除/重生成与目录统计接口；在 `job.json` 中记录再生成所需的安全参数和可复用音频引用，不保存代理密钥或其他凭据。前端增加卡片动作、筛选状态、确认对话框和错误反馈。

### 阶段 E：体验验收与文档

对安装、恢复、网络配置、难度设置、预览速度、分页和删除做端到端回归；使用真实生成曲包检查预览时间映射和 MCZ 不变性；在 README 中加入安装向导和操作说明。需要实机导入或试玩的结果单独标记，不用自动化格式检查代替。

### 多曲工作流实现记录（2026-10-02）

- YouTube 搜索改为每页最多 20 条，支持时长筛选、继续加载、视频 ID 去重、频道/时长/来源展示；单批最多 20 首并共用提交时的参数快照。
- 新增持久化 FIFO 队列、队列页、等待任务取消、失败后继续和重试入队。重启时等待任务转为暂停、运行任务转为中断；只有用户点继续后才恢复。
- 新增时间定位的密度、疑似静音和细分音符告警。结构轨道冲突保留对应预览并阻止 MCZ 导出；普通启发式提示不改谱。
- 保存共享母谱候选、时间信息、种子、模型标识和参数；可单档再生成、浏览/恢复版本，并保留每版 MCZ。
- 新增 `tools/hardware_benchmark.py`，覆盖两引擎的短/中/长完整曲生成和三种双任务组合。并行默认关闭；只有本机 GPU 与驱动匹配、所有测试及曲包校验通过且保留至少 2 GiB 显存，才能手动选 2 路。
- 自动测试覆盖搜索分页/过滤、批次上限与快照、FIFO 恢复/取消、失败续跑、质检告警、版本恢复及并行门槛。真实显卡压力基准需要三段本地测试音频，本轮未运行，因此当前实例保持串行；手机端导入与试玩仍需实机验收。

## 6. 验证矩阵

- **安装：** 全新环境、已有主环境、只装 MuG、只装 V32、全部安装、重复安装、断网续装、镜像/代理错误、哈希不匹配、无 GPU。
- **界面：** 390 px、720 px、1366×768、1920×1080；键盘可操作；主流程不需要编辑高级参数；设置保存和恢复。
- **预览：** 六档与长条、流速两端及默认值、暂停恢复、音频跳转、专注模式、不同 DPR 和浏览器缩放。
- **曲包库：** 搜索、过滤、分页、直接下载、重新生成、删除确认、磁盘占用更新、运行中任务保护。
- **兼容与安全：** 现有 API/CLI 参数兼容；模型版本与 SHA-256 不变；不得把模型权重、用户音乐、代理凭据或安装日志提交到 Git。

## 7. 暂不纳入本次范围

增加模型或训练模型、自动上传音乐到云端、自动配置系统级代理、批量不可逆删除、替用户判断音乐授权，以及宣称生成等级与 Malody 官方评级一致。

## 8. 关键依赖与风险

- 镜像和代理质量随时间、地区和运营商变化，必须保持可配置并在失败时回到官方源；模型校验不能省略。
- MuG 与 V32 权重、代码及生成内容受各自上游条款约束；安装向导应在下载前展示来源和限制。
- 预览画面只能辅助检查，不等于 Malody 游戏内判定、皮肤、游戏滚速或手机触控手感；说明应持续可见。
- 自动删除会造成数据丢失；必须逐项确认并在删除完成后验证占用空间。
- 个人上传音频不应意外保留在历史目录之外；保留周期、删除范围和曲包再生成所需音频应保持透明。
