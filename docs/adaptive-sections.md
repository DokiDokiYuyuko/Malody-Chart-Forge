# 段落节奏与动态难度

同一难度可以随歌曲的节奏活动起伏。新生成默认开启段落适配，旧任务缺少此设置时沿用原有策略，不改写历史谱面。

## 如何使用

普通工作台可开关「自动适配高速与段落变化」。高级台还能调整增强强度、查看冻结的段落计划，以及分别设置六档的模型条件。强度为 0 时不增加动态权重；峰值、同刻上限、同轨间隔和长条上限仍以用户设置为准。

高级台的独立生成保存模型原谱，再另存只处理结构与硬上限的可玩候选；不会为了达到平均 NPS 重排原谱。快速分层先生成母谱，再按实际起音与各段的软目标选键。两种方式都保留模型输出与实际采样条件，便于找出问题来自哪一步。

## 节奏证据

- 使用原曲 44.1 kHz 双声道 PCM 建立全曲计划；采样范围是唯一时间基准。
- 起音活动与 BPM 分开分析：持续响亮的声音不等于快速节奏，人声唱得很密也不一定代表音乐的拍速变化。
- 局部 BPM 比较半速、原速与倍速支持度。低置信度或倍速歧义时，不增加 BPM 权重，也不移动音符时间。
- 导入 MC/模型生成的 BPM 只作为节拍参考，不能成为已验证的声学结论。用户手动确认的锚点可作为已知参考。
- 核心段通常约 16 秒，最长 32 秒，前后保留 4 秒上下文。只收集核心拥有的音符；上下文不重复进入成品。

节奏活动按原曲相对起伏计算。每档动态软目标的最大变化为 Easy ±15%、Medium ±20%、Hard/Expert/Master ±25%、Lunatic ±20%；模型条件的最大变化分别为 ±0.3 / 0.4 / 0.5 / 0.6 / 0.6 / 0.6。强度滑块按比例缩小这些范围。BPM 只提供小幅辅助权重，不能覆盖休止段。

计划包含原曲 PCM 哈希、设置快照、节拍参考、核心与上下文、置信信息、逐档条件和硬上限。提交后冻结计划，混音、人声、伴奏及融合使用同一份父源计划。改变设置或源音频会产生新身份，不假装复用另一套条件的结果。

## 采音与排键

模型中不同的实际时间点不再因小于 50 ms 就提前合并；近时和弦也不自动视为重复。声音证据不足的候选可能不被选入最终谱面，但原模型输出保留。

快速分层按每段、每个短乐句分配软预算，不能在起音不足时凭空填网格或制造满押。四轨占用、滚动一秒峰值和长条约束连续检查；同侧手部负担作为软偏好，不声称能够证明真人可玩。

独立生成先评审模型原谱，规则处理另存候选。分轨联合制谱先保留两份原谱，融合阶段只消费一次总预算；后续规则候选不会再执行一次密度分层。

## 验证与边界

自动用例覆盖固定种子、计划身份、关闭后的兼容行为、快速活动与 BPM 歧义、静音、31–49 ms 的独立模型时点、跨段长条、单次融合预算和保留来源信息。真实曲目用《初音ミクの消失》的 28–44 秒段验证混音、分轨、融合与旧版 MCZ 结构。

音符增多或告警减少不等于谱面质量提高。需要用同一原曲比较候选，试听并分别记录手机四指、键盘 4K 的人工反馈。模型的排键倾向、生成条件与音符数都不是 Malody 官方等级。

## Implementation

`section_plan.py` builds a canonical PCM-based plan; `adaptive_difficulty.py` applies bounded section/phrase targets and continuous lane constraints. `advanced_generation.py` consumes native V32 time contexts or MuG context crops. The ordinary pipeline uses the same inference adapter. Raw attempts, seeds and actual conditions remain local; no intermediate model files enter MCZ archives.

## 节奏分析窗口与缓存

「分析节奏与拍速」分开展示已有 BPM 锚点和逐段候选。一个导入 BPM 锚点不会阻止分析多段活动，也不说明 RoFormer 只处理了一段。约 72 / 144 / 288 BPM 的半、原、双倍候选若支持度接近，保留歧义，不自动增加变化点。

全曲计划按源码版本、原曲 PCM、完整采样数、有效分析设置和节拍参考精确复用；修改模板或锚点时生成新计划。融合参数变化使用冻结音频证据重算预算，保存独立融合计划，不重新运行模型。详见[「私は雨」接口验收](rain-workflow-validation.md)。
